# Agent workflow

Generated by `uv run unicad-mcp --write-workflow docs/agent-workflow.md`, which runs the example below against a temporary workspace; `tests/test_mcp_workflow.py` fails when this file is out of date. Do not edit by hand.

The server hands the same workflow to every MCP client in two places: the instructions sent when a session starts, and the prompts a client can list and run. Both are reproduced here, followed by a complete session.

## Server instructions

```text
UniCAD builds Indian (IS/CEA) solar EPC drawing sets from a typed project model. You state engineering intent through tools; drawings are deterministic renders of the model. Never give drawing coordinates. Site and layout coordinates are local metres produced by the site and layout tools.

Workflow, in order. Every edit returns the new revision and a `problems` list; read it before the next step.
0. Company: company_list shows the profiles (title block, drawing numbering, layers, symbols, rule thresholds). For a new company run company_onboard(dxf_path, answers) with its DXF and questionnaire, fix what it reports as failed, and check the result with company_preview_sheet.
1. project_create(name, client, segment, site, grid_voltage_v). Read the `assumptions` it returns: they are placeholders. company_assign(project_id, profile_id) puts the project on the company's profile. project_list / project_get show what exists.
2. project_design_basis(project_id, ...) before any design: site values (ambient_min_c, ambient_max_c, altitude_m), limits (vdrop_dc_max, vdrop_ac_max, dc_ac_ratio_target, power_factor), fault levels per system voltage, earthing inputs (soil resistivity from the Wenner test) and lightning protection inputs (level from the risk assessment). A value you set replaces its placeholder. If you change site values, limits or fault levels after the network exists, build the network again (step 5).
3. site_import(project_id, file_path) from KML, KMZ, GeoJSON, DXF or a coordinate list; site_set_feature / site_remove_feature fix what the survey missed; site_set_setbacks takes clearances from the design basis (none are assumed); site_summary shows the buildable area.
4. design_strings sizes a string for a module and inverter. layout_place(project_id, module, modules_per_string, strings_per_inverter, ...) then puts tables on the buildable area (tables default to one string per row, half tables only where they hold whole strings), splits them into inverter blocks of whole inverters and assigns strings; it reports an error when a table cannot hold a string. For rooftops the inverter station stands on a roof unless station_x/station_y give its place. layout_summary and layout_blocks read the result.
5. network_autobuild(project_id, template, ac_kw or dc_kwp, module, inverter) builds the complete electrical network from intent, links layout strings and sizes breakers for the prospective fault (declared levels and transformer-fed LV faults) and cables for the declared fault levels. Use catalog_search / catalog_get for equipment ids. For hand edits use network_add_group, network_add_node, network_connect, network_update and network_remove; model identical equipment once with a count.
6. validate(project_id) runs the engineering rules and says which issue purposes (approval, construction, as_built) are blocked; its `next` says when a rebuild is the fix. explain_finding(project_id, rule_id, subject) gives the formula, inputs and sources. Fix errors with network_update / layout_place / site tools or by re-running network_autobuild, then validate again until no errors remain. Never edit a value just to silence a rule: change the design. earthing_design(project_id, soil_resistivity, ...) and lps_design(project_id, method, level, ...) design the earth grid and lightning protection (run layout_place first); earthing_summary reads them back.
7. Deliverables: drawings_render(project_id, kinds=["all"]) renders the complete set (drawing register, SLD, layout, earthing, LPS, string diagrams, cable schedule, BOM) as DXF, PDF or DWG with the company's numbers and layers; drawings_preview shows a sheet as PNG. cable_schedule and bom also export the schedules alone (xlsx, dxf or pdf).
8. project_snapshot(project_id, label) names the issued revision; project_diff compares revisions (per-feature site changes, per-block layout changes, sheet changes). Use revision= on read tools to inspect an older state.

Rules: mark every assumption you make and tell the user; take equipment values only from the catalog; if a tool reports a blocker or an error finding, fix the model rather than working around it. Prompts new_rooftop_project, new_utility_project, new_bess_project and revise_after_comments give step plans for the common jobs.
```

## Prompts

### `new_rooftop_project(name)`

```text
Build a rooftop PV drawing set for "<name>" with UniCAD tools. State intent only; never invent ratings or coordinates.

1. Ask the user for anything missing: grid voltage, DC or AC capacity, inverter make/size, module make/Wp, roof survey file (KML, KMZ, GeoJSON, DXF), roof setbacks from the design basis, soil resistivity, lightning protection level. Mark anything you assume.
2. project_create(name, client, segment="ci_rooftop", site, grid_voltage_v). Read back `assumptions` and replace placeholders with site data when the user has it.
3. site_import(project_id, file_path). Check `problems` and `imported_by_kind`; add missed obstacles with site_set_feature (kind="obstacle", height_m). site_set_setbacks with distances from the design basis, then site_summary for the buildable roof area.
4. catalog_search for the module and inverter, catalog_get to check ratings, design_strings(project_id, module, inverter) for the string length.
5. layout_place(project_id, module, mounting="rooftop_flush" or "rooftop_tilted", target_dc_kwp, ...). Check layout_summary: DC kWp reached, blocks, row pitch.
6. network_autobuild(project_id, template="ci_rooftop", ac_kw or dc_kwp, module, inverter). Read `blockers` and `assumptions`. For hand changes use network_add_node / network_connect / network_update.
7. validate(project_id). For each error, explain_finding(project_id, rule_id, subject), change the design (network_update, layout_place, site tools), and validate again until there are no errors. Report warnings to the user.
8. earthing_design(project_id, soil_resistivity, fault_ka, clearing_s) and lps_design(project_id, method, level); validate again.
9. Deliverables: drawings_render for the drawing sheets, cable_schedule and bom (xlsx). Quote the paths and the assumptions each returns.
10. project_snapshot(project_id, label) once the set is agreed, e.g. "issued-approval-r0".
```

### `new_utility_project(name)`

```text
Build a utility-scale PV drawing set for "<name>" with UniCAD tools. State intent only; never invent ratings or coordinates.

1. Ask the user for anything missing: AC and DC capacity, inverter or PCS make/size, module make/Wp, MV voltage level, grid voltage at the point of interconnection, site boundary file, setbacks from the design basis, soil resistivity, earth fault level and clearing time, lightning protection level. Mark anything you assume.
2. project_create(name, client, segment="utility", site, grid_voltage_v). Read back `assumptions`.
3. site_import(project_id, file_path) for boundary, exclusions, water, roads and transmission lines; fix classification with kind_mapping or site_set_feature. site_set_setbacks (boundary_m, exclusion_m) from the design basis; site_summary for the buildable acres.
4. catalog_search for module, inverter (or pcs) and transformer; design_strings(project_id, module, inverter) for the string length and DC/AC ratio.
5. layout_place(project_id, module, tilt_deg, road_every_rows, target_dc_kwp, block_dc_kwp or n_blocks, modules_per_string). Check layout_summary (block_balance, gcr) and layout_blocks.
6. network_autobuild(project_id, template="utility_string" or "utility_central", module, inverter, inverters_per_block). Layout strings are linked to the network automatically. Read `blockers` and `assumptions`.
7. validate(project_id); explain_finding for each error; fix and re-validate until no errors remain.
8. earthing_design(project_id, soil_resistivity, fault_ka, clearing_s, ...) and lps_design(project_id, method, level, ...); validate again.
9. Deliverables: drawings_render for the drawing sheets, cable_schedule and bom. Quote paths, totals and assumptions.
10. project_snapshot(project_id, label) once the set is agreed.
```

### `new_bess_project(name)`

```text
Build a battery energy storage drawing set for "<name>" with UniCAD tools. State intent only; never invent ratings or coordinates.

1. Ask the user for anything missing: storage power (kW) and energy (kWh), AC- or DC-coupled, PCS and battery make, grid voltage at the point of interconnection, PV capacity when hybrid, export limit, site file. Mark anything you assume.
2. project_create(name, client, segment="bess" or "hybrid", site, grid_voltage_v). Read back `assumptions`.
3. site_import(project_id, file_path) when a site file exists; site_set_setbacks from the design basis.
4. catalog_search(kind="pcs") and catalog_search(kind="battery"), then catalog_get to confirm ratings.
5. network_autobuild(project_id, template="bess_ac" (AC-coupled), "bess_dc" (DC-coupled) or "hybrid", bess_kw, bess_kwh, pcs, battery, export_limit_kw; for hybrid also ac_kw or dc_kwp, module, inverter). Read `blockers` and `assumptions`.
6. validate(project_id); explain_finding for each error; fix with network_update and re-validate until no errors remain.
7. earthing_design and lps_design when a layout exists; validate again.
8. Deliverables: drawings_render for the drawing sheets, cable_schedule and bom. Quote paths and assumptions.
9. project_snapshot(project_id, label) once the set is agreed.
```

### `revise_after_comments(project_id, comments)`

```text
Revise project "<project_id>" after review comments.

Comments to address:
<comments>

1. project_revisions(project_id) and project_snapshot the issued revision first if it has no label (e.g. "issued-r0"), so the baseline is kept.
2. For each comment decide which part of the model it changes: site (site_set_feature, site_remove_feature, site_set_setbacks), layout (layout_place), network (network_update, network_add_node, network_connect, network_remove, or network_autobuild to rebuild), earthing or lightning (earthing_design, lps_design). Change the model, never the drawing. If a comment needs a value you do not have, ask the user.
3. validate(project_id); explain_finding for each error; repeat until no errors remain.
4. project_diff(project_id, from_revision="<baseline label>") and summarise per comment what changed. Say which comments you did not address and why.
5. Re-run drawings_render, cable_schedule and bom, then project_snapshot with the next revision label (e.g. "issued-r1").
```
